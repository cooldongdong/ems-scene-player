# 消防員場 事件腳本產生器（本地版）

選環境 ／ 急救事件 ／ 突發狀況，自動從素材庫組出情境：上方是場景底層的四張卡（環境影像、環境聲音、病患照片、病患聲音），
下方是勾選的每個突發狀況各自一組（綠幕影片＋聲音）。一次急救訓練常常要演複數個突發狀況，所以勾幾項就出幾組，
不是每次隨機挑一項；教官依現場節奏按各組的「播放這組」逐一觸發。
純靜態網站：`index.html` + `scenario-data.yaml` + `assets/`，沒有後端、沒有 Google Drive。

產生情境後可按「開啟投影視窗」，把獨立視窗移到投影螢幕。視窗會盡量以螢幕可用範圍開啟，
環境影片會靜音、循環並以 cover 滿版播放；環境圖片與影片 fallback 也會以 cover 滿版顯示。
若瀏覽器未允許自動最大化，可在投影視窗右上角按「進入全螢幕」。
病患照片的疊加開關就在「病患樣貌照片」卡的照片下方，預設關閉；開啟後，透明病患照片會完整保留比例疊在環境上。
同一區塊有「大小／水平／垂直」三個滑桿可以邊看投影邊調（大小＝照片可佔畫面的比例，水平／垂直＝照片中心點位置），
按「重設版面」回到預設。調好的版面在重新產生情境後會沿用，只會換成新的病患照片，
而且會依當下的環境素材存進瀏覽器（詳見「版面會依環境記住」）。

素材資料來自提案者提供的 6 個情境（`scenario-data.md`），已拆成可重新組合的素材：
住宅 OHCA、街道打架止血、工地墜落骨折、街道車禍、KTV 酒醉、套房自傷。
原本的 6 個情境都能原樣重現，也能跨情境重組（例如工地 × 家屬崩潰哭喊）。

## 跑起來

```bash
python3 -m http.server 8000
# 開 http://localhost:8000
```

用 `file://` 直接開會因為瀏覽器安全限制讀不到 YAML，所以要走本地伺服器（或 VS Code Live Server）。

伺服器會佔住整個 terminal（印出 `Serving HTTP on ...` 之後不會回到提示符），那是正常的，要一直開著；
按 Ctrl+C 就等於關掉網站。要確認是不是已經在跑了，用 `lsof -nP -iTCP:8000 -sTCP:LISTEN` —— 有輸出就是還活著，
這時再跑一次會拿到 `OSError: [Errno 48] Address already in use`，不是壞掉，是不用再開一個。

### 改了 `js/` 之後要強制重新整理

`python3 -m http.server` **不送 `Cache-Control` 標頭**，瀏覽器會對 `js/scenarios.js` 套用啟發式快取、
可能不問伺服器就用舊的。而 `scenario-data.yaml` 是用 `fetch(..., { cache: 'no-cache' })` 抓的，每次都是新的。

**於是會出現「新資料配舊程式」**——症狀是頁面報 `Scenarios.xxx is not a function`。
解法是強制重新整理（Mac `⌘+Shift+R`、Windows `Ctrl+F5`）。頁面偵測到這種情況時會直接這樣提示你。

想一勞永逸就用會送 no-store 的版本開伺服器：

```bash
python3 -c "
import http.server as h, socketserver, functools
class C(h.SimpleHTTPRequestHandler):
    def end_headers(self):
        self.send_header('Cache-Control','no-store, must-revalidate'); super().end_headers()
socketserver.TCPServer.allow_reuse_address = True
socketserver.TCPServer(('127.0.0.1',8000), C).serve_forever()"
```

## 情境（scenario）

面板最上面有一排快捷鈕，點一下套用整組設定並直接產生；滑鼠停留可以看到完整內容。
目前的選單三層可以排出 5×6 = 30 種基本組合，但素材庫沒有填滿每一格，選到空格只會看到
「查無符合的素材」——情境就是「這組確定跑得動」的驗證過名單，讓第一次用的人不必靠試誤去找。
當三個選單剛好等於某一組情境時，該按鈕會亮起；手動改動後就會熄掉。

一個情境 = **素材組合（環境×急救事件）＋ 一串照順序演的簡報頁（slides）**。
清單寫在 `scenario-data.yaml` 的 `scenarios:` 底下，格式與編輯規則見該段註解。

**不要寫 `complications` 欄位。** 這個情境用到哪些突發狀況，是從所有「啟用中」的簡報頁
自動推導出來的。多寫一份就是第二份真相，遲早出現「勾了但沒有任何一頁用到」或反過來的矛盾。

簡報頁的 `enabled: false` 代表**播放時跳過，但仍留在清單裡**——用途是現場臨時抽掉一個橋段，
不必真的刪掉它。省略視為啟用。動作型別目前只有兩種（刻意收斂）：`wait`（停住等教官口述）
與 `complication`（播某個突發狀況）。

值對不上 `options:` 的情境會被整筆跳過，並在瀏覽器 console 留一行警告；
整段 `scenarios:` 刪掉的話，頁面會自動不顯示這個區塊，其他功能不受影響。

**目前這 7 組是「素材齊全」，不等於「情境合理」**——它們是把 30 種組合逐一比對素材庫後，
四個基本角色都取得到素材的那幾組。實際播過覺得不合適就直接改掉那一筆；
反過來，補完素材之後也要記得把新的組合加進來，這份名單不會自己長。

### 三層編輯器

情境清單、簡報頁、編輯頁是鑽入式的三層，**主視窗與投影視窗的側邊欄各有一份、共用同一份狀態**——
在哪一層、載入哪個情境、播到第幾步，兩邊永遠一致。單機編排時用側邊欄（投影視窗全螢幕會蓋住主視窗），
接了投影機之後用主視窗控制（否則等於把編輯介面投給學員看）。

| 層 | 能做什麼 |
| --- | --- |
| 情境 | 選情境、新增、複製、刪除、匯出 YAML、匯入 |
| 簡報頁 | 前進／後退、每頁的啟用開關、拖曳排序、新增頁、重新命名情境 |
| 編輯頁 | 改標題、增刪與排序動作、複製或刪除這一頁 |

**流程步驟不等於簡報頁**：多片段的突發狀況會展開成多個步驟。既有 UI 本來就是一段一段播的，
一頁只播第一段的話後面幾段永遠播不到。例：「路口車禍」3 頁 → 5 步。

快捷鍵（**主視窗與投影視窗都能用**）：

| 鍵 | 作用 |
| --- | --- |
| `→` `Space` `PageDown` | 下一步（尚未開始時＝從第一步開始）|
| `←` `PageUp` | 上一步 |
| `Home` / `End` | 第一步 / 最後一步 |
| `Esc` | 停止並回到未開始 |

焦點在選單、輸入框或按鈕上時快捷鍵一律放行，不會在你調滑桿時誤跳頁。

改動內建情境不會動到 `scenario-data.yaml`——它會變成一份「覆蓋內建」的自訂情境，
在清單上按「還原成內建」就回到原樣。純自訂情境按「刪除」才是真的消失。

### 自訂情境存在哪

自訂情境存在瀏覽器的 localStorage（鍵值 `ems-scene-player:scenarios`，格式 JSON），
**同 id 會覆蓋內建情境**，新的 id 則接在清單後面。清掉 localStorage 就回到純內建的 7 組，
這也是「還原」的做法。工作副本壞掉時會自動退回內建情境，不會讓整個站台開不起來。

純靜態網站沒有後端，寫不回 `scenario-data.yaml`，所以資料分兩種格式：
**localStorage 用 JSON**（只存字串、往返精確、沒有人會手讀）、
**匯出檔用 YAML**（可以直接貼回 `scenario-data.yaml` 變成內建情境）。
匯入時 YAML 與 JSON 都吃——JSON 是 YAML 的子集，同一個 parser 直接解得動。

## 素材把關

**選得到卻演不出來是最傷的一種挫折**：使用者以為自己設定好了，按下去卻什麼都沒有。

5 環境 × 6 急救事件 × 6 突發狀況 = **180 種勾選組合，實際上只有 46 種會出現東西**。
所以「有沒有素材」必須在選之前就看得見：

- **突發狀況勾選框**依目前的環境×急救事件停用並劃掉，滑鼠停留說明原因
- 切換環境或事件時，**原本勾著但已不可用的會自動取消**（留著會產生一組空的卡片）
- 選單下方一行說明**這個組合缺哪些基本素材**，以及可用的突發狀況有幾個
- **編輯器的突發狀況下拉**同樣把關，沒素材的標成「（此情境無素材）」且不能選
- 情境清單上，引用到沒素材狀況的情境（多半是匯入別人的）標 `⚠` 並在 tooltip 列出是哪些

判斷「能不能用」與實際挑素材**共用 `js/scenarios.js` 的同一份實作**（`eligibleAssets`）。
各寫一份的話，畫面上說能用、按下去卻沒東西，兩邊還都覺得自己沒錯。

綠幕人物只要有**影片**就算可用——沒有專屬配音時會用綠幕影片的原聲，那仍然演得出來。
基本四角色裡標了 `type: none` 的**不算缺**，那是資料作者刻意留白（例如住宅室內沒有環境聲音）。

## 素材頁（`assets.html`）

給**補素材的人**看的，不是給教官跑訓練用的。主畫面下方有連結進去。

- **覆蓋表**：環境 × 急救事件 30 格，每格四個方塊對應環境影像・環境聲音・病患照片・病患聲音
  （✓ 有素材／— 刻意留白／! 查無），加上該格可用的突發狀況數。**點任一格會回到產生器並套用那個組合**。
- **摘要**：先講缺口再講齊全——目前是「7/30 齊全、22 格缺病患照片、46/180 種勾選真的會出現東西、1 格一個突發狀況都沒有」
- **素材清單**：依 role 分組，圖可看、音可聽、影片可播，附 id、檔案路徑、台詞、片段編號與全部標籤
  （標籤留空會顯示「不限」，因為留空是刻意的決定，不是漏填）

覆蓋表與把關用的是**同一組資料層函式**（`coverageMatrix` / `baseCoverage` / `availableComplications`），
所以這一頁說能用的組合，產生器就一定選得到。

## 測試

資料層（`js/scenarios.js`）是不碰 DOM 的純函式，用 Node 內建的測試跑，不需要安裝任何東西：

```bash
node --test
```

測試載入的就是瀏覽器實際跑的那兩份檔案（`js/scenarios.js` 與 `vendor/js-yaml.min.js`），
不是複製品，所以測試綠代表瀏覽器裡的行為也是這樣。

判斷邏輯請一律寫在 `js/scenarios.js`，不要寫進 `index.html` 的畫面層——寫在畫面層就測不到。

## 六個角色

| role | 內容 |
| --- | --- |
| `environment_video` | 環境影像（優先影片，必要時可改顯示圖片） |
| `ambient_sound` | 環境聲音 |
| `patient_photo` | 病患樣貌照片 |
| `patient_voice` | 病患聲音 |
| `complication_video` | 突發狀況綠幕影片（約 10 秒） |
| `complication_voice` | 突發狀況聲音與台詞（該段綠幕是影片時只顯示台詞、不播音檔，見下） |

## 加素材的流程

1. 檔案丟進 `assets/<role>/`。
2. 在 `scenario-data.yaml` 的 `assets:` 底下補一筆，填 `id` / `type` / `role` / `file` / `tags` / `description`；`file` 只填檔名，前端會依 `role` 自動組成路徑。
   判斷影片／圖片／聲音時**副檔名優先於 `type`**，所以換素材時直接換檔名就能用（`type` 還是建議填對）。
   突發狀況聲音可以多填一個 `line:` 寫台詞，卡片上會用引號框起來顯示。
3. 重新整理頁面即可，不用改任何程式碼（YAML 是 no-cache 讀取的，重整就會拿到新版，不用清快取）。

環境影片可加上可選的 `fallback` 欄位，影片檔讀不到或瀏覽器無法播放時，會依序改顯示指定的 `.jpg`／`.jpeg`／`.png`。`fallback` 也只填檔名，可填一個檔名或檔名陣列：

```yaml
- id: ev001
  type: video
  role: environment_video
  file: home_livingroom.mp4
  fallback:
    - home_livingroom.jpg
    - home_livingroom.png
```

若該環境一開始就只有圖片，也可直接使用 `type: image`、`role: environment_video` 與 jpg/png 的 `file`；畫面會直接顯示圖片。

`tags` 的每個維度留空陣列 `[]` = 該維度不限，任何選擇都適用（通用素材）。
每個 role 至少留一筆完全通用的素材，可以避免某些選項組合出現「查無素材」。

「這個情境刻意沒有這個素材」（例如住宅 OHCA 沒有環境聲音、OHCA 病患沒有聲音）寫 `type: none` 且不填 `file`，
卡片會顯示「此情境無此素材」，跟「查無素材」的資料缺口區分開。

`options:` 區塊決定三個選單顯示哪些項目、順序如何，由人工控制。環境選項依 `室內`／`室外` 分組，畫面會以選單群組呈現；素材的 `tags.environment` 仍填實際環境名稱，例如 `住宅客廳` 或 `市區街道`。若整段刪掉，程式會退回「從素材標籤自動蒐集」。

## 選取邏輯

1. **必要條件**：素材的 `tags.environment`／`tags.medicalEvent` 要符合選擇，或該欄位為空（通用）。
2. **突發狀況為加分匹配**：場景底層的四個角色，有命中的素材優先，沒有就退回通用素材（卡片上會標「命中突發狀況」）。
   - 反過來說，標了特定突發狀況的素材，在該狀況沒被勾選時不會被選到。
   - `complication_video` 與 `complication_voice` 只在有勾選狀況時才出現，不用通用素材頂替。
   - 勾了 N 個突發狀況就產生 N 組，**每組只吃自己那一個狀況的素材**，
     所以綠幕影片和台詞一定來自同一個事件，不會出現「家屬哭喊的影片配上工地同事的台詞」。
3. 每個 role 各自隨機挑一筆（突發狀況群組是「每組每個 role」各挑一筆）；
   「重新產生」在同條件下重跑，且會盡量避開上一次選到的那筆。

播放控制分兩層：上方的「播放場景」只播環境／病患那四張卡並同步投影視窗，不會一次把所有突發狀況都放出來；
每組標題右邊的「播放這組」只播該組的綠幕影片＋聲音；「全部停止」把全部媒體與投影都停掉歸零。
場景底層會一直放著，按突發狀況不會打斷它；但突發狀況一次只演一段，按下一段時前一段自動收掉。

**一段演出只出一個聲音**，看那一段的綠幕素材是哪一種：

- **綠幕是影片** → 用影片自己的原聲（真實素材都有現場收音）。「突發狀況聲音」卡就不放播放器了，
  只留台詞文字和配音 prompt，不然兩個聲音會疊在一起。
- **綠幕只有劇照** → 影片沒得播，就播「突發狀況聲音」卡的配音 mp3。

投影視窗的影片一律靜音，不然同一支影片會在控制台和投影各響一次。

## 一個突發狀況拆成好幾個片段

同一個突發狀況可以拆成好幾段，讓教官依現場節奏一段一段觸發（例如爭吵 → 越吵越兇 → 動手）。
作法是在素材上加 `segment:` 數字，綠幕素材與台詞標同一個 segment 就會配成同一段：

```yaml
- id: cv004-2
  type: video
  role: complication_video
  file: drivers_argue_2_gs.mp4
  segment: 2
  tags:
    environment: []
    medicalEvent: []
    complication: [肇事雙方爭吵]
  description: 第二段：越吵越兇
```

沒寫 `segment` 就是第 1 段，所以現有只有一段的素材完全不用動。
拆成多段時，組標題會顯示「N 個片段」與整組的「停止」，組內每段自己一個區塊，各有「播放這段」和「停止」。
綠幕的大小／位置／去背是**整組共用一份**——同一個人站在同一個位置，不用每段重調。
在任一段拖滑桿，同組其他段的滑桿會跟著移動，投影也即時更新；不同突發狀況之間互不影響。

`segment` 和 `file:` 陣列是兩回事：`file:` 陣列是同一句話的不同 take，只會播其中一個；
`segment` 是接續演出的不同段落，每段都會演到。同一個 segment 底下放多筆素材，就是那一段的多個候選，每次產生隨機挑一筆。

## 綠幕人物疊到投影上

按某一組的「播放這組」時，該組的綠幕素材會**即時去背**疊到投影視窗上（在環境與病患之上）。

疊上去的畫面**不會自己消失**：

- 剛疊上去時停在**第一格**（按「預覽定位」就是這個狀態，人物先站在場景裡不動）
- 按播放後演一次，結束**停在最後一格**
- 要收掉才按該段／該組的「停止」、上方的「全部停止」，或重新產生情境

同一時間最多只有一段在投影上，改播另一段會直接接替。
綠幕素材**可以是影片，也可以是一張綠幕劇照**（`complication_video` 收 mp4 也收 jpg/png），劇照本來就是停著的。

綠幕影片卡的下方有四個滑桿：

| 滑桿 | 意思 |
| --- | --- |
| 大小 | 人物可佔畫面的比例（同時當成 `max-width: N vw` 與 `max-height: N vh`，比例不會被拉扁） |
| 水平／垂直 | 人物中心點在畫面上的百分比位置 |
| 去背 | 綠色的判定容差。留綠邊就往上加，人物開始破洞就往下降 |

旁邊的「預覽定位」會把人物疊上投影並停在第一格，方便訓練前先把位置調好，再按一次結束預覽。
停著的時候（含播完停在最後一格）拖滑桿，投影上的那一幀會即時重畫。
每個突發狀況各自記自己的大小／位置／去背設定，重新產生情境後會沿用。

## 版面會依環境記住

病患照片和綠幕的大小／位置／去背都會存進瀏覽器的 `localStorage`，**key 是當下那筆環境素材**，
所以關掉瀏覽器再打開、調好的位置還在，不用每次訓練前重調。

用素材 id 而不是環境名稱，是因為同一個環境可能有好幾張背景（例如「市區街道」有騎樓和路口兩張），
人物該站的位置本來就不一樣。換到別的背景會變成那張背景自己的一份設定，換回來又回到原本調好的位置；
沒調過的背景就是預設值。

存的只有版面數值，「疊加到投影視窗」開關不會被記住——每次開始訓練都是乾淨畫面。
想全部重來就清掉瀏覽器的網站資料，或一個一個按「重設版面」。

去背是瀏覽器即時做的（canvas 逐幀把接近綠幕色 `#00b140` 的像素轉透明，用 YCbCr 色度距離判斷，
所以打光不均也還撐得住），**素材照舊丟原始的綠幕 mp4 就好，不用先轉檔**。
拿到真實素材後如果綠底色差很多，調「去背」滑桿即可；容差開到上限仍不會吃掉白色或深色制服。
運算量用 canvas 內部寬度上限 960px 壓住，素材換成 1080p 也不會變重。

按「重新產生」時，換掉素材的卡片會閃一下橘框，卡片上的 `N 筆可選` 標籤會說明這個角色在目前條件下有幾筆素材；
只有 1 筆時會直接標「此條件僅 1 筆素材，重新產生不會變」——素材庫還小的時候多數角色會是這種狀態，這是資料量問題不是壞掉。

## 突發狀況聲音的配音 prompt

6 段突發狀況聲音都在 `scenario-data.yaml` 裡附了 `tts:` 欄位，是給 ElevenLabs **Eleven v3** 用的 prompt，
卡片上會出現「Eleven v3 配音 prompt」的摺疊區塊，展開就能看到 voice／settings 建議並一鍵複製。

綠幕素材已經是有收音的實拍影片時，這些 prompt 與 `line` 台詞就變成**給人看的**（現場演員對詞、日後補錄用），
播放時的聲音來自影片本身的音軌；只有綠幕是劇照的段落，才會真的播到這裡產出的配音檔。

寫這些 prompt 時遵循的幾點（依 ElevenLabs 的 v3 prompting 指引）：

- audio tag 用**小寫方括號**寫在句子裡（`[crying]`、`[angry]`、`[shouts]`、`[rushed]` …），可以疊用
- tag 的效果**跟所選 voice 有關**：voice 的情緒幅度不夠時，v3 可能會把 tag 當文字念出來，換一個情緒表現力強的 voice 即可
- `⋯⋯` 產生自然停頓、逗號控制換氣、大寫字表示重音（中文改用驚嘆號堆疊）
- `Stability` 建議 **Creative**（情緒最飽滿但偶爾失控，多生幾次挑一條）
- 每段都寫成 4-5 句而不是只有原本那一句台詞：太短的文字 v3 情緒容易不穩，而且綠幕影片是 10 秒，配音長度要跟得上。用不到的句子剪掉即可

兩個要人工處理的例外，已寫在 YAML 註解裡：**車禍的緊急煞車聲**要另外找音效疊上去（不要用 TTS 生），
**三字經**目前只寫到「靠」的程度，更重的字眼可能被平台過濾，需要就用現場收音補。

參考：[Prompting Eleven v3](https://elevenlabs.io/docs/best-practices/prompting/eleven-v3)、[What are Eleven v3 Audio Tags](https://elevenlabs.io/blog/v3-audiotags)
